# 초기 RALPLAN 합의 계획: RealSense D435 + moteus 기반 사람추종 2륜 휠레그드 보조 로봇

## Summary
이 계획은 취약 사용자 가까이에서 동작하는 안전중요 보조 로봇 개념에 대한 초기 합의 문서다. 구현이 아니라 학습 범위, 제품 선택, 단계별 검증, 취약 사용자 적용 한계, 향후 Obsidian 정리 구조를 명시한다. 권고 방향은 **아기 우선이 아니라 노인 우선**이며, 이유는 노인 지원 시나리오가 과업 정의, 감독 체계, 안전 경계, 가치 검증 면에서 훨씬 현실적이고 규제 및 윤리 리스크가 낮기 때문이다.

## 1. 문제 정의와 명시적 범위
### 문제 정의
목표는 실내에서 지정된 보호 대상자 또는 보호자의 승인을 받은 사용자 주변을 저속으로 따라다니며, 물건 동반 이동, 상태 확인 보조, 호출 응답, 비진단적 패턴 알림을 제공할 수 있는 2륜 휠레그드 보조 로봇의 초기 기술 계획을 세우는 것이다.

### 명시적 범위
- RealSense D435 기반 근거리 사람추종과 주변 거리 인지 전략 정리
- BLDC + FOC + moteus 기반 구동계 후보 선정
- 휠레그드 구조에서 필요한 센서, 안전 하드웨어, 전원 구조 정리
- 취약 사용자 대상 활용 시나리오와 금지 범위 구분
- Phase 0~4 순차 개발 및 검증 로드맵 작성
- 향후 Obsidian 저장용 노트 경로와 개요 제안

### 제외 범위
- 제품 소스 구현, 펌웨어 작성, 제어기 튜닝 실행
- 실제 Obsidian 파일 작성
- 의료 진단, 낙상 판정 확정, 영유아 직접 접촉 보조 자동화
- 무인 야외 주행, 계단 주행, 자율 문개폐, 비승인 추종

## In scope / Out of scope
### In scope
- 안전중요 보조 로봇의 초기 아키텍처 옵션 비교
- 제품 스택 권고와 선구매 대 지연구매 구분
- 학습 로드맵과 단계별 검증 계획
- 노인 우선, 영아 제한 시나리오 정리

### Out of scope
- 상세 기구 설계 도면
- 법규 인증 패키지 작성
- 양산 BOM 확정
- 사용자 데이터 정책 최종안

## 2. RALPLAN-DR 요약
### Principles
1. 안전 경계가 성능보다 우선이다.
2. 사람추종은 저속 실내 보조로 제한하고, 접촉 없는 거리 유지가 기본이다.
3. 센서 한 개의 낙관적 해석에 의존하지 않는다.
4. 초기 단계는 화려한 AI보다 관측 가능성, 정지 가능성, 수동 개입성을 우선한다.
5. 취약 사용자 대상 기능은 반드시 보호자 또는 운영자 감독 흐름 안에 둔다.

### Decision Drivers 상위 3
1. 취약 사용자 근접 운용에서의 안전성 및 실패 시 피해 크기
2. 부품 공급 가능성, 개발 문서 성숙도, 재현 가능한 실험성
3. 실내 저속 사람추종과 휠레그드 밸런스 제어를 분리해 단계적으로 검증할 수 있는지 여부

### Viable Options
#### 옵션 A: D435 + 단일 보조 컴퓨터 + moteus r4.11 + 보수적 2륜 자가균형 휠레그드 프로토타입
- 구성: Apple Silicon 개발 환경은 상위 계획용으로만 쓰고, 실제 로봇 런타임은 Linux 기반 x86 또는 Jetson 급 보조 컴퓨터에서 운용. D435는 0.3~3m 실내 추종용 주 depth 센서. 모터 제어는 moteus r4.11 CAN FD. 사람추종은 비전 추종, 균형 및 하부 제어는 로컬 실시간 제어기로 분리.
- 장점:
  - D435의 글로벌 셔터 depth와 근거리 범위가 실내 추종에 적합하다.
  - moteus r4.11은 공식 문서와 공급 가용성이 비교적 명확하다.
  - 상위 인지와 하위 FOC 제어를 분리하기 쉬워 단계 검증에 유리하다.
- 단점:
  - macOS는 librealsense가 컴파일 가능하나 검증 플랫폼이 아니므로 런타임은 별도 Linux가 사실상 필요하다.
  - 자가균형 휠레그드 제어 난도가 높아 추종보다 안정화가 먼저 병목이 된다.
  - 단일 depth 카메라 의존 시 유리, 검은 천, 근접 가림에서 취약하다.

#### 옵션 B: D435 + 보조 2D 안전 라이다 추가 + moteus r4.11 + 초기에는 비자가균형 저속 베이스
- 구성: D435는 사람 ID 및 근거리 depth, 2D 라이다는 바닥면 장애물과 최소 정지 보호, 모터 제어는 동일하게 moteus r4.11. 초기 섀시는 휠레그드 외형을 유지하더라도 Phase 2까지는 자가균형을 강제하지 않고 저중심 수동 안정 구조로 제한.
- 장점:
  - 센서 중복으로 근접 장애물과 가림 대응이 더 낫다.
  - 추종 알고리즘과 보행 또는 균형 문제를 초기에 분리해 일정 리스크를 낮춘다.
  - 취약 사용자 시연에서 안전 설명이 더 쉽다.
- 단점:
  - 부품 수와 통합 복잡도가 증가한다.
  - 진정한 휠레그드 균형 제어 학습이 뒤로 밀린다.
  - BOM과 전력 예산이 늘어난다.

#### 옵션 C: 카메라 추종보다 UWB 태그 또는 리모컨 우선, 비전은 보조
- 구성: 사람추종 핵심을 비전이 아니라 태그 기반 상대 위치 추정으로 두고, D435는 장애물 회피와 사용자 인식 확인 보조로 둔다.
- 장점:
  - 가림과 조명 변화에 덜 민감하다.
  - 초기 안전 반경 제어가 단순하다.
- 단점:
  - 사용자에게 태그 휴대 부담이 생긴다.
  - 무태그 자연스러운 추종이라는 목표와 거리가 있다.
  - 취약 사용자 대상 채택성이 떨어질 수 있다.

### 권고 선택
현재는 **옵션 B를 권고**한다.
- 이유:
  - 취약 사용자 근접 운용에서 센서 다중화와 비자가균형 초기 베이스가 가장 보수적이다.
  - 사람추종 가치 검증과 휠레그드 동역학 검증을 같은 단계에 억지로 묶지 않아도 된다.
  - D435와 moteus는 공식 정보와 공급 근거가 있지만, 전체 시스템 안전성은 depth 카메라 단독으로는 방어적이지 않다.

### 대안이 지금 덜 적합한 이유
- 옵션 A 비선호 이유: 기술적으로 가능하지만 안전 여유가 너무 작고, 균형 실패와 추종 실패가 동시에 사용자 근접 문제로 이어질 수 있다.
- 옵션 C 비선호 이유: 초기 안전 데모에는 유리하나 사용성 목표와 자연스러운 보조 경험을 약화시킨다.

## 3. 권장 제품 스택
### Compute platform
#### 권장
- 런타임 메인: Ubuntu 기반 미니 PC 또는 NVIDIA Jetson Orin Nano 급
- 개발 보조: 현재 macOS Apple Silicon 저장소는 알고리즘 탐색, 로그 분석, 노트 정리에 사용

#### 이유
- D435는 macOS에서 컴파일 가능해도 검증 플랫폼이 아니므로 실제 로봇 런타임은 Linux 우선이 안전하다.
- 사람추종 perception과 로깅, 관측성 도구를 안정적으로 운용하려면 로봇 런타임 환경을 별도 고정하는 편이 낫다.

### Depth camera
#### 권장
- Intel RealSense D435 1대
- defer 후보: 필요 시 전방 RGB 보조 카메라 또는 상부 광각 카메라 추가

#### 이유
- 글로벌 셔터 depth, 약 0.3~3m 실내 추종 범위, 최대 1280x720 90fps 스펙은 근거리 보조 추종에 적합하다.
- 단, 유리, 반사, 근접 가림, 좁은 FOV 한계는 설계상 전제해야 한다.

### Motor controllers
#### 권장
- mjbots moteus r4.11

#### 이유
- 10~44V, CAN FD, 비교적 높은 전류 처리와 문서 성숙도로 프로토타입 제어기에 적합하다.
- qdd100 beta 3는 공식 존재는 확인되지만 현재 재고/가용성이 불안정하므로 초기 핵심 의존 대상으로 두지 않는다.

### Actuators / motors / gear / encoders strategy
#### 권장 전략
- Phase 1~2: 바퀴 구동은 저 KV BLDC + 감속기 + 절대 또는 고해상도 증분 엔코더 조합
- 다리 또는 자세 조절 축은 초기에는 최소 자유도만 두고, 필요 시 별도 감속기 일체형 액추에이터로 확장
- 직접 구동보다 **저속 고토크 감속형** 우선

#### 이유
- 취약 사용자 근접에서는 과한 속응성보다 예측 가능한 감속 응답과 정지 재현성이 중요하다.
- 초기에는 자유도 수를 줄여 FOC 튜닝, 전류 제한, 열 거동, 백드라이브 특성을 먼저 이해해야 한다.

### Base locomotion sensors and safety hardware
#### 필수
- IMU
- 휠 엔코더
- 모터 온도 또는 드라이브 온도 모니터링
- 범퍼 또는 접촉 스위치
- 전방 근접 안전 센서 추가 레이어: 2D 라이다 또는 초음파 보조
- 하드웨어 E stop
- 소프트웨어 watchdog
- 전원 차단 릴레이 또는 contactor
- 상태 표시등과 부저

#### 이유
- D435 단독은 바닥면 저형 장애물, 반사체, 가림에 취약하다.
- 취약 사용자 가까이에서는 시각화보다 즉시 정지 체인이 더 중요하다.

### Battery / power / E stop / docking or charging considerations
#### 권장
- 24V 또는 36V 계열 배터리 팩을 우선 검토하고, 제어기와 모터 전류 피크를 기준으로 퓨즈 및 배선 규격을 넉넉히 산정
- 충전 중 구동 금지 인터락
- 물리 E stop 2개 이상: 사용자 접근 위치 1개, 운영자 후면 1개
- 초기는 자동 도킹보다 수동 충전 우선

#### 이유
- 자동 도킹은 접촉, 정렬, 화재, 충전 인터락까지 추가 복잡도를 만든다.
- 초기 파일럿은 충전 자동화보다 안전 정지와 로그 회수가 더 중요하다.

### Must buy now
- D435
- moteus r4.11 수량 최소 2개 이상
- 시험용 저속 BLDC + 감속기 + 엔코더 세트
- IMU, 휠 엔코더, E stop, contactor, 퓨즈, DC 전원 계측 장비
- Linux 런타임 컴퓨트 플랫폼
- CAN FD 인터페이스 및 개발 케이블
- 벤치 전원공급기와 절연 보호 장비

- 장시간 배터리 팩 대용량화
- 취약 사용자 전용 UI 하우징 고도화

## 4. 학습 로드맵
### Phase 0: Desk study
- FOC 기초: dq 변환, 전류 루프, 속도 루프, 토크 상수, back EMF, 전류 제한
- BLDC 실무: 모터 상수 읽기, 발열, 감속기 백래시, 엔코더 정렬
- D435 실무: 깊이 노이즈, 반사체 실패 모드, 캘리브레이션, 타임스탬프 정합
- 보조 로봇 HRI: 감독자 개입 설계, 비진단 원칙, 취약 사용자 설명 책임
- 산출물: 위험 목록 초안, 부품 shortlist, 측정 지표 목록

### Phase 1: Benchtop actuator + FOC
- 바퀴 1축 또는 2축 벤치 리그 구성
- moteus 전류 제한, 속도 제한, 열 관측, watchdog 검증
- 엔코더 정렬 및 저속 추종 오차 측정
- 비상정지 후 재기동 절차 정의
- 종료 기준: 과전류 없이 반복 가능한 저속 제어, 정지 명령 재현성 확보

### Phase 2: Mobile base
- 저중심 베이스 제작, 초기에는 비자가균형 또는 보조 캐스터 포함 허용
- IMU + 엔코더 융합, 저속 주행, 제동 거리 측정
- D435 없이도 안전 정지와 원격 수동 제어가 성립해야 함
- 종료 기준: 빈 실내에서 반복 주행, 장애물 앞 정지, 수동 복구 절차 검증

### Phase 3: Person following
- D435 기반 대상 추적, 거리 유지, 재식별 실패 시 정지 또는 보호자 호출
- 2D 라이다 또는 보조 근접 센서와 충돌 방지 결합
- 추종 속도 제한, 사용자 측면 접근 금지, 후방 접근 금지 정책 구현 계획 수립
- 종료 기준: 성인 감독자 대상 제한 공간 실험에서 안전 반경 유지

### Phase 4: Assistive pilot
- 노인 우선 파일럿: 약 복용 알림 보조가 아니라 물건 운반 동행, 호출 응답, 생활 동선 동반
- 보호자 관찰 체크리스트, 로그 검토, 실패 모드 보고
- 영아 관련은 직접 추종보다 보호자 보조 시나리오만 제한 검토
- 종료 기준: 감독 하의 짧은 세션에서 가치와 위험이 모두 문서화됨

## Sequencing and dependencies
1. 안전 요구와 비목표 확정
2. D435 런타임 환경을 macOS가 아닌 Linux 기준으로 고정

## 5. 취약 사용자 적용 분석
### 노인 우선 사용 사례
1. 실내 저속 동행: 보행 보조가 아니라 물건 운반 동행, 호출 응답, 지정 위치 따라오기
2. 생활 지원 보조: 물, 리모컨, 약 상자 운반 보조. 단, 복약 판단은 하지 않음
3. 패턴 알림: 평소보다 이동이 적음, 호출 후 응답 지연, 특정 구역 접근 반복 같은 비진단 패턴을 보호자에게 요약
4. 원격 케어 보조: 보호자가 원격으로 로봇 위치, 마지막 관측, 수동 호출 상태를 확인

### 왜 노인 우선인가
- 사용 목적이 비교적 명확하고 감독자 워크플로 설계가 쉽다.
- 직접 접촉 없이도 가치가 나온다.
- 실패 시 즉시 정지와 보호자 개입으로 리스크 완화가 가능하다.
- 영아는 예측 불가능한 급접근, 바닥 자세 변화, 접촉 위험 때문에 같은 추종 개념을 그대로 적용하기 어렵다.

### 영아 및 아기 관련 사용 사례와 명시적 안전 한계
#### 제한적으로 가능한 범위
- 보호자 동반 환경에서 방 안 반대편까지 물건 운반
- 아기 주변 환경 관찰 보조 메모 초안 생성
- 보호자 호출 시 카메라 시야 공유 보조

#### 금지 또는 강한 제한
- 아기를 직접 따라다니는 자동 추종
- 침대, 유아 매트, 좁은 놀이 공간 근접 주행
- 울음, 질식, 건강 상태를 진단처럼 판단하는 알림
- 보호자 부재 상황에서 자동 감시 대체

### AI가 현실적으로 할 수 있는 것
- 사람 재식별 보조와 거리 유지 상태 추정
- 이동 패턴, 호출 빈도, 구역 체류 같은 비진단 요약
- 위험 이벤트 후보 로그 분류와 검토 우선순위 제안
- 관찰 기록 초안 작성과 보호자용 요약 생성

### AI가 해서는 안 되는 것
- 질병, 인지저하, 통증, 낙상 여부를 단정하는 판단
- 영아 상태를 의료적 의미로 해석하는 알림
- 감독자 승인 없이 추종 대상을 자율 변경
- 불확실한 상황에서 이동 지속을 선택하는 행위

## 6. Deliberate mode
### 사전 실패 분석: 정확히 3개 시나리오
1. **가림 후 오추종 시나리오**
   - 복도에서 대상 사용자가 코너를 돌고 다른 사람이 시야에 들어오자 로봇이 잘못된 사람을 따라감
   - 결과: 사생활 침해, 충돌, 보호자 신뢰 상실
   - 방지: 재식별 불확실성 상승 시 즉시 정지, 음성 또는 앱 확인, 보호자 승인 전 재출발 금지

2. **균형 또는 제동 실패 시나리오**
   - 배터리 전압 저하나 제어 튜닝 불안정으로 급정지 시 차체가 앞쪽으로 기울며 사용자 다리에 접촉
   - 결과: 낙상 유발 가능성
   - 방지: 초기 비자가균형 베이스 허용, 감속 한계 보수 설정, 저전압 시 성능 저하 모드, 물리 범퍼와 E stop 배치

3. **센서 맹점 접근 시나리오**
   - 검은색 낮은 발판 또는 반사체를 D435가 안정적으로 보지 못해 근접 충돌
   - 결과: 발 끼임, 물건 파손, 사용자 놀람
   - 방지: 보조 라이다 또는 근접 센서 추가, 바닥 장애물 전용 테스트 세트, 미확인 영역에서는 속도 상한 강제

### 확장 검증 및 시험 계획
#### Unit
- FOC 전류 제한 로직, 속도 제한, watchdog 상태 전이
- 재식별 confidence 임계값 처리와 정지 정책
- E stop 입력 처리, 저전압 경보 상태 전이
- 로그 이벤트 스키마와 타임스탬프 일관성

#### Integration
- D435 depth + 추종 추정 + 주행 명령 연결 시험
- moteus 제어기 + 엔코더 + IMU 데이터 융합 검증
- E stop, contactor, 소프트웨어 watchdog 연쇄 정지 검증
- 센서 장애 주입: depth drop, CAN 지연, 엔코더 이상치

#### End to end
- 빈 공간 직선 추종
- 좁은 실내 회전 구간에서 대상 상실 후 안전 정지
- 감독자 개입 후 재시작 절차
- 저조도, 반사체, 바닥 장애물 환경 시나리오
- 노인 우선 파일럿에서 물건 동반 이동 과업 완료율과 개입 횟수 기록

#### Observability
- 주행 상태, 목표 거리, 추종 confidence, depth 품질, 전류, 온도, 배터리 전압, E stop 상태를 동시 로깅
- 사고 직전 10초 버퍼 로그 보존
- 현장 운영용 상태등 코드와 부저 패턴 표준화
- 실험마다 운영자 메모와 동기화된 세션 리포트 작성

#### Safety checks
- 전원 인가 전 체크리스트: 바퀴 공회전, 통신, E stop, 센서 상태
- 실험 전 속도 상한 잠금
- 사람 근접 실험은 2인 이상 배치, 1명은 E stop 전담
- 매 세션 후 발열, 볼트 체결, 케이블 마모, 범퍼 동작 점검
- 취약 사용자 세션은 성인 감독자 반복 통과 전 금지

## 7. ADR stub
### Decision
취약 사용자 대상 초기 사람추종 보조 로봇은 **노인 우선**, **옵션 B 아키텍처**, **D435 + 보조 근접 안전 센서 + moteus r4.11 + Linux 런타임** 조합으로 단계 검증한다.

### Drivers
- 안전 우선과 즉시 정지 가능성
- 공급 가능성과 문서 성숙도
- 추종 지능과 하부 안정화의 단계 분리 가능성

### Alternatives considered
- 옵션 A: D435 단독 중심 자가균형 휠레그드
- 옵션 C: UWB 또는 태그 중심 추종

### Why chosen
- 옵션 B가 가장 보수적이며 취약 사용자 근접에서 실패 비용을 줄인다.
- 사람추종 가치 검증과 휠레그드 제어 난도를 분리할 수 있다.

### Consequences
- 초기 BOM 증가
- 진정한 자가균형 휠레그드 완성 시점은 늦어질 수 있음
- 대신 안전 검증과 파일럿 설득력이 높아짐

### Follow ups
- D435 Linux 런타임 환경 실증
- moteus 벤치 리그 부품 확정
- 안전 요구 체크리스트와 운영 절차서 초안 작성
