# ON DAMM 윤리·사회적 설계 전환안

작성 기준일: 2026-08-30

> 이 문서는 제품·연구 설계를 위한 내부 기준이며 법률 자문을 대체하지 않는다. 아동 대상 실제 연구 전에는 소속기관 IRB와 개인정보 보호 담당자의 검토를 받는다.

## 1. 결론

ON DAMM의 중심을 **얼굴·행동을 잘 분류하는 AI**가 아니라 **아동이 통제할 수 있는 최소 증거 기반 지원 연속성 시스템**으로 둔다.

한 문장으로 표현하면 다음과 같다.

> ON DAMM은 아동을 평가하는 시스템이 아니라, 담당자가 바뀌어도 검토된 지원 맥락이 사라지지 않도록 반복 기록·정리·검색을 돕는 로컬 우선 인수인계 인프라다.

기술적 도전은 줄어들지 않는다. 오히려 다음을 하나의 검증 가능한 시스템으로 연결하는 것이 핵심 종합설계가 된다.

```text
목적별 동의·아동 assent
→ 최소 수집·event-only capture
→ 관찰 사실과 해석의 분리
→ 다중 사람 검토와 이견 보존
→ 승인된 지원 맥락만 canonical 기록으로 승격
→ 역할 기반 인수인계
→ 철회·파기·감사 가능성
```

## 2. 왜 이 방향이 목표에 더 맞는가

세 검토 문서는 공통적으로 다음 문제를 지적한다.

- 현장의 진짜 문제는 담당자 변경 시 지원 경험과 맥락이 사라지는 것이다.
- AI의 역할은 진단·평가가 아니라 기록·정리·검색 부담을 줄이는 것이다.
- 진단 점수나 등급은 아동에 대한 선입견과 교육적 낙인을 만들 수 있다.
- 카메라와 생체·행동 데이터는 단순 보안이 아니라 동의, 통제, 철회, 파기까지 포함한 데이터 주권의 문제다.
- “위험한 기술을 못 한다”가 아니라 “현장의 문제와 아동의 권리를 위해 기술 역할을 의도적으로 제한했다”라고 설명해야 한다.

따라서 발표의 주어도 AI가 아니라 서비스 연속성이어야 한다.

| 약한 서사 | 목표에 맞는 서사 |
| --- | --- |
| 표정 인식 AI를 만들었지만 진단에는 쓰지 않는다 | 서비스 단절을 줄이기 위해 관찰 증거를 최소 수집하고 사람이 검토하도록 설계했다 |
| 정확도가 낮아서 사람이 확인한다 | 낙인과 자동결정 방지를 위해 해석 권한을 사람에게 남긴다 |
| 개인정보를 로컬에 저장한다 | 아동·보호자가 목적별 동의, 중단, 열람, 정정, 철회를 통제한다 |
| 영상 세 번 중 한 번만 저장한다 | 반복 episode를 RAM에서 확인하고 필요한 현재 증거만 저장하는 데이터 최소화 기술이다 |

## 3. 절대 넘지 않을 제품 경계

ON DAMM 제품·발표·아동 대상 연구 경로에서는 다음을 금지한다.

1. 얼굴·시선·자세로 감정, 의도, 집중도, 흥미, 순응도, 선호 또는 ASD 여부를 추론하지 않는다.
2. 아동에게 점수, 등급, 위험도, 순위 또는 정상/비정상 라벨을 부여하지 않는다.
3. AI 출력만으로 교육, 복지, 징계, 치료 또는 서비스 접근 결정을 내리지 않는다.
4. 상시 녹화, 몰래 촬영, CCTV·인터넷 얼굴 수집 또는 목적 외 재사용을 하지 않는다.
5. 서비스 이용 동의와 연구 참여·모델 학습·외부 API 전송 동의를 묶지 않는다.
6. 거부나 철회에 불이익을 주거나, 보호자의 동의를 아동 본인의 지속적인 거부보다 우선시키지 않는다.
7. 사람이 확인하지 않은 관찰 후보를 canonical dossier나 다음 지원 전략에 자동 반영하지 않는다.

EU AI Act는 생체정보로 감정이나 의도를 식별·추론하는 시스템과 단순히 겉으로 드러난 표현·몸짓·움직임을 감지하는 기능을 구분한다. 다만 단순 움직임이 감정·의도 추론에 사용되는 순간 그 경계가 사라진다. 교육기관에서의 감정 추론은 원칙적으로 금지되는 사용에 포함되므로, 위 경계는 홍보 문구가 아니라 데이터 모델, API와 테스트로 강제해야 한다.

## 4. 현재 구현에서 잘 잡힌 부분

현재 코드에는 이미 좋은 설계 기반이 있다.

- DINO 없이 MediaPipe-only로 실행할 수 있고, 제품 TCN 입력에서 시선·머리 자세와 DINO를 제외한다.
- `79 features × 60 frames → 64D` 출력은 감정명이 아니라 개인 내 움직임 episode를 표현한다.
- 겹치는 TCN window를 반복 횟수로 세지 않고 독립 episode로 합친다.
- 1~2회 영상은 저장하지 않고 짧은 RAM buffer만 사용하며, 세 번째 현재 episode만 선택적으로 저장한다.
- 원격 GPT 전송은 기본값이 아니고, MP4 전체가 아닌 제한된 frame에 매번 별도 동의를 요구한다.
- 세 역할의 독립 검토와 이견을 보존하고, 합의와 별개의 명시적 승격을 요구한다.
- 동의 철회 시 dossier와 영상·패턴 UI를 `withdrawn_locked` 상태로 차단한다.
- 감정·진단·집중도 판단 금지 문구와 사람 검토 경계가 코드와 UI에 들어 있다.

이 요소들은 “분류 정확도”보다 **데이터 최소화, 불확실성 처리, 인간 감독을 구현한 기술**로 발표하는 편이 좋다.

## 6. 가장 먼저 구현할 `Rights Gate`

다음 기능은 모델 개선보다 먼저 구현한다.

### 6.1 목적별 동의 모델

```text
ConsentGrant
  subject_id
  purpose: service_record | camera_capture | research | model_training | remote_review
  data_categories
  guardian_consent
  subject_assent: yes | no | not_obtainable
  explanation_mode
  granted_at / expires_at / revoked_at
  form_version / protocol_id / actor_signature
```

- `camera_capture`가 활성이고 아동의 현재 거부가 없을 때만 카메라를 연다.
- `research` 동의가 있어도 `model_training`과 `remote_review`는 자동 허용하지 않는다.
- 법정대리인 동의는 아동에게 쉬운 방식으로 설명하고 의사를 확인하는 절차를 대체하지 않는다.
- 동의 기록에는 동의하지 않아도 받을 불이익이 없다는 사실과 중단·철회 방법을 포함한다.

### 6.2 거부가 가능한 카메라 UX

문서의 “카메라 적응” 제안은 다음처럼 수정한다.

```text
녹화 OFF 상태의 사전 적응
→ 쉬운 설명과 이해 확인
→ 항상 보이는 REC 표시
→ 정지 카드·버튼·제스처 연습
→ 매 구간 시작 전 재확인
→ 초기 적응 구간은 저장하지 않음
```

목표는 호손효과를 줄이기 위해 아동이 관찰을 잊게 만드는 것이 아니다. 원격 관찰을 하더라도 촬영 사실과 중단 방법은 계속 명확해야 한다. 아동이 말, 몸짓, 시선 회피, 카메라 가림 등 사전에 합의한 거부 신호를 보이면 보호자의 최초 동의와 무관하게 해당 구간을 중단하고 저장하지 않는다.

### 6.3 철회와 파기

`withdrawn_locked`는 안전한 첫 단계지만 파기는 아니다. 다음 두 단계로 나눈다.

1. 즉시 처리 중단: 카메라, 분석, 조회, 내보내기, 원격 전송을 잠근다.
2. 검증 가능한 파기: 대상 데이터 inventory를 만든 뒤 원본 영상, event clip, frame, CSV, dossier, embedding/prototype, export, cache와 백업의 처리 상태를 기록한다.

파기 완료 후에는 개인 내용을 담지 않은 최소한의 tombstone만 별도 법적 근거와 보존기간이 있는 경우에 한해 남긴다. 파기 결과에는 삭제 대상, 성공·실패, 남은 법적 보존 항목, 수행자와 시간을 포함한다.

## 7. 관찰 사실과 해석의 분리

데이터는 세 층으로 분리한다.

```text
L0 sensor candidate
  "12.4~12.8초 입꼬리 주변 landmark 변화"
  자동 만료, 공식 기록 아님

L1 human-reviewed observation
  "활동 전환 직후 같은 움직임이 세 번 관찰됨"
  관찰 사실만, 감정·의도 없음

L2 approved support context
  "전환 10초 전에 그림 카드로 예고했을 때 활동 전환이 원활했음"
  근거 session과 승인자 포함, 인수인계에 사용
```

L0에서 L2로 자동 승격하는 경로는 만들지 않는다. 이 구조가 AI 낙인 차단과 서비스 연속성을 동시에 보여 주는 핵심 기술이다.

## 8. 연구 질문도 바꾼다

아동 대상 연구의 주요 성과지표를 분류 정확도에서 다음으로 전환한다.

### 주요 지표

- 새 담당자가 필요한 지원 맥락을 찾는 데 걸리는 시간
- 인수인계 핵심 항목의 누락률
- 교사의 기록·정리 시간과 검토 부담
- 담당자 간 지원 계획의 일관성
- AI 후보 중 사람이 유용하다고 승인한 비율과 이견률
- 저장된 원본 영상 시간/전체 관찰 시간 비율
- 철회 요청부터 처리 중단·파기까지 걸리는 시간
- 아동의 카메라 거부·중단 횟수와 중단 성공률

### 안전 지표

- 감정·의도·진단 표현이 공식 기록에 유입된 횟수
- 잘못된 후보가 교사 판단에 영향을 준 사례
- 역할 외 접근, 목적 외 사용, 만료 후 잔존 파일 수
- 검출 실패와 오탐이 특정 조건에 집중되는지 여부

### 권장 평가 순서

1. 합성 데이터와 성인 팀원으로 파기·권한·감사 흐름을 검증한다.
2. 교사·사회복지사와 비식별 시나리오 기반 usability test를 한다.
3. 장애 당사자·보호자·현장 종사자가 참여하는 공동설계로 설명 방식과 중단 신호를 정한다.
4. IRB 승인과 목적별 동의 체계를 갖춘 뒤 최소 규모 실제 환경 pilot을 한다.
5. 효과가 입증되기 전에는 서비스 의사결정에 사용하지 않는다.

## 9. 발표 데모의 권장 흐름

현재 temporal demo를 다음 이야기로 재구성한다.

1. **문제:** 담당자 교체 때 효과적이었던 지원 맥락이 메모와 구두 전달 사이에서 사라진다.
2. **권리 확인:** 목적, 저장 범위, 중단 방법과 보존기간을 확인한다.
3. **최소 수집:** 첫 두 episode는 RAM에서만 비교하고 영상은 남기지 않는다.
4. **증거 저장:** 세 번째 반복에서 현재의 짧은 구간만 저장한다.
5. **사람 검토:** 세 역할의 관찰 사실과 이견을 나란히 보존한다.
6. **명시적 승인:** 지원에 유용한 맥락만 별도 행위로 dossier에 반영한다.
7. **인수인계:** 새 담당자가 근거와 승인 이력을 함께 확인한다.
8. **철회·파기:** 한 번의 요청이 모든 파생 데이터 inventory와 파기 영수증으로 이어지는 모습을 보여 준다.

이 흐름은 “AI가 무엇을 알아냈는가”보다 “AI가 얼마나 적게 저장하고, 어디서 멈추며, 사람의 책임 있는 판단을 어떻게 이어 주는가”를 보여 준다.

## 10. 구현 순서

### P0: 다음 개발 묶음

1. `ConsentGrant`와 중앙 `RightsGate.can_process()`를 추가한다.
2. 카메라·분석·GPT·승격 API가 모두 Rights Gate를 통과하도록 한다.
3. `withdraw_and_purge --dry-run/--execute`와 파기 영수증을 구현한다.
4. ON DAMM 제품·데모에서 `emotion`, `interest`, `attention`, `compliance` 출력을 제거하고 금지 테스트를 추가한다.
5. 녹화 OFF 적응 단계, REC 표시와 접근 가능한 중단 입력을 추가한다.

### P1: 실제 기관 pilot 전

1. 인증, RBAC, 전자서명과 접근 감사
2. 저장 암호화, key 분리, 데이터 종류별 TTL과 자동 파기
3. 열람·정정·이의제기·파기 요청 UI
4. IRB/protocol/consent version gate
5. 기본권·개인정보 영향평가와 incident response 문서

### P2: 운영 검증

1. 현장 업무시간과 인수인계 누락률 비교
2. 아동·보호자·교사 관점의 수용성·부담 평가
3. 조건별 검출 실패와 사람 검토 부담 평가
4. 외부 독립 윤리·보안 검토

## 11. 이번 구현에서 완료한 권리 보호 장치

다음 P0 항목은 코드와 웹 화면에 반영했다.

- 촬영, 연구 전용 지표, 모델 학습, 원격 검토를 서로 다른 동의 목적으로 저장한다.
- 서명 문구 원문은 저장하지 않고 SHA-256 확인값만 남긴다.
- 실제 카메라는 유효한 촬영 동의와 교육 전 확인이 모두 있을 때만 열린다.
- 교육 전 확인은 쉬운 설명, 촬영 장치 인지, 카메라 OFF 적응, 중단 버튼 연습, 현재 참여 의사를 모두 요구한다.
- 아동이 웹의 큰 **촬영 싫어요 · 중단** 버튼을 누르면 실행 중인 카메라가 로컬 기록철을 반복 확인해 중단한다.
- 중단 상태는 단순 재개 버튼으로 풀 수 없고, 새 교육 전 확인을 처음부터 완료해야 해제된다.
- 표정·흥미·주의 지표가 포함된 오프라인 분석기는 연구 전용 동의가 없으면 종료 코드 5로 차단한다.
- 철회 후에는 웹 또는 `scripts/ondamm_purge.sh`로 삭제 대상을 먼저 확인하고, 정확한 확인 문구를 입력해야 실제 삭제한다.
- 삭제 확인서는 아동 이름·ID·영상 경로를 남기지 않고 대상 ID의 해시와 유형별 건수만 보존한다.

현재 삭제 기능은 이 저장소가 직접 관리하는 로컬 원본, 반복 패턴, 검토 기록, 학습 실행, 인수인계와 소유 표시된 연구 분석 산출물을 대상으로 한다. 운영체제 백업, 사용자가 별도로 복사한 파일, 이미 전송된 외부 시스템 자료까지 자동 삭제했다고 주장하지 않는다. 실제 기관 도입 전에는 백업과 외부 처리자까지 포함한 파기 절차를 별도로 검증해야 한다.

## 12. 실제 적용 후 임시기간 평가 방안

현 시점에는 실제 기관에서 서비스 단절 감소 효과를 측정하기 어렵다. 따라서 이를 구현 완료 조건이나 성능 주장으로 사용하지 않고, 시스템 적용 뒤의 제한된 임시 운영 계획으로 남긴다.

1. 먼저 합성 데이터와 성인 팀원으로 중단·철회·파기 성공률을 확인한다.
2. 기관 도입 후 4~8주의 관찰 기간에는 기존 업무를 대체하지 않고 병행한다.
3. 새 담당자가 지원 맥락을 찾는 시간, 인수인계 누락 항목, 기록 부담을 익명 집계한다.
4. 아동의 중단 요청은 성공적으로 즉시 반영됐는지만 확인하고, 거부 횟수를 아동 평가 지표로 사용하지 않는다.
5. 교사·보호자·사회복지사의 이견률과 검토 부담을 함께 기록한다.
6. 임시기간 종료 시 아동·보호자 관점의 불편과 이익을 먼저 검토하고, 효과가 불명확하거나 부담이 크면 확대하지 않는다.

IRB 승인, 기관 개인정보 보호 검토와 당사자 공동설계가 없으면 실제 아동 대상 효과 평가를 시작하지 않는다.
